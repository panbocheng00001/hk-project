## 三、必须记住的坑（本轮新发现，已写进代码）

### 3.1 认证型转发代理 **不能**用 curl_cffi 的 chrome 画像

```
impersonate=chrome / chrome136  →  curl (28) timed out after 25s
                                  或 curl (35) TLS connect error: OPENSSL_internal:invalid library
impersonate=None + HTTP/1.1     →  200 708B，1.9s ✅
```

BoringSSL 的 h2/ALPS 过这种 `host:port:user:pass` 转发口会卡死/报 TLS 错误；
`curl.exe` 同出口却正常 —— 和 11-13 记录的 `SSL certificate: unable to get local issuer`
是同一类问题（客户端侧，不是代理 MITM）。

**结论：纯脚本走这类代理，一律 `--impersonate none --http1`。** 站点不挑战时，
UA/Accept-Language 仍是 chrome157，不影响业务判断。

### 3.2 偶发 `curl (56) RECV_RESET`

09:12:07、09:14:31 各出现一次，`sniper._retry()` 一次即恢复。
不是 400，不构成「出口被判死」；判死的唯一信号是 **HTTP 400**。

### 3.3 `proxies.txt` 带 BOM 会把 host 写脏

之前用 PowerShell `Set-Content -Encoding UTF8` 写入，行首多出 `\ufeff`，
`free_host` 解析成 `\ufeff14.215.163.195`（curl 能容忍，但日志和比对会被污染）。
已改用 `UTF8Encoding($false)` 写入，py 读回 `b'14.215.163.195:2018:jlipiLP7OB:boOKSVho\r\n'`。
