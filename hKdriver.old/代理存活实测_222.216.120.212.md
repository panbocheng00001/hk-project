## 一句话结论

**是「一小时」级别的，但形态是：到点断线 → 恢复后换出口 IP。**
不是"一小时后彻底失效"，而是"一小时换一次出口"——对绑 IP 的门票来说，这比失效更麻烦。

## 对抢号的实际影响

门票（`HWWAFSESID` / `HIK0kat3rt9xO` + 排队放行位）**绑出口 IP**。这个代理每小时换一次出口，所以：

1. **跨轮换点的票必废。** 票寿命 20 分钟，能否活过轮换点取决于你在哪一刻铸的。
2. **只看 abs3 返回 200 抓不到这件事。** 实测：出口从上海换到石家庄后，用旧票请求 abs3 仍然 200（网关对 SPA 壳页不严格校验 IP）。所以必须**显式比对出口**。
3. 已经修进 `token_pool.py --health`：每张票先探一次 `ipinfo.io`，与记录的 `egress_ip` 不一致就判 `dead` 并排队重铸。

```
[13:09:08] p001-browser ⚠ 出口变了 1.1.1.1→14.127.169.56 → 票作废，待重铸
```

（这条是单元验证：把票的出口改成假值 1.1.1.1，health 立刻抓到。修它时还发现一个真 bug——原代码在比对出口**之前**就把 session 关了，检查等于没做。）

## 17:00 怎么排班

轮换点 = **首次连接 + 60 分钟**，所以只要把首次连接安排在 16:40 之后，轮换点就落在 17:40 之后，正好覆盖 17:00–17:20 的窗口：

| 时间 | 动作 |
|---|---|
| ≤16:39 | **不要**碰这个代理（连一次就开始计时） |
| 16:40 | 首次连接 → 铸票进池 |
| 16:41–16:59 | 每 5 分钟 `--health` 一次（顺带盯出口有没有变） |
| 17:00 | 放行 → 用票；票与出口同一租期内，安全 |
| 17:40 | 轮换点，若还在抢就重铸一次 |

## 两条硬提醒

1. **抖动是常态**：3.5% 的 502 + 每小时一次断线。任何请求都要带重试，并且必须有备用出口（本地直连也行，只是出口在深圳）。
2. **它仍然不是"你的"线路**：朋友给的机器，是否被别人共用、是否随时收回都不可控。当作"能撑一小时的高质量备用"，别当作唯一依赖。
