# 内地驾照 → 香港正式驾照（免试签发）抢名额作战手册

> 实测环境：2026-11-08（周日）。本文所有"实测"数据都来自本目录脚本对运输署真实系统的探测。

---

## 0. 三句话结论

1. **今天（周日）没有名额是正常的**：名额只在**每个工作日 17:00** 更新一次，周末不放号。实测页面原文：
   > 「你所选择的服务现时没有可供预约的时段。系统每个工作日下午5时更新预约名额。经更改或取消的预约时段，其名额会重新开放。」
2. **"抢"不是抢刷新速度，是抢 17:00 那次随机排队**：16:30–17:00 进池子的人，在 17:00 被**随机洗牌**，早进没有优势；17:00 之后进的按实际时间排序。所以战术是"16:30 后进池 + 多一个会话 + 17:00 一到手上资料齐、40 秒填完"。
3. **决定成败的是那 20 分钟**：进到系统后必须在 20 分钟内完成登记，所以资料要提前做成一张"速填卡"，OTP 邮箱要守着。

## 1. 资格自检（先确认能办，再去抢）

免试签发香港正式驾驶执照（内地驾照）必须**用文件证明**同时满足：

| # | 条件 | 内地驾照的实操要点 |
|---|---|---|
| a | 驾照由《道路交通（驾驶执照）规例》附表4 认可地区签发，**仍有效或过期不超过 3 年** | 中国内地在名单内；必须是**正式**驾照，实习期/学习驾照不行 |
| b | 准驾车型对应 | 免试只适用于**私家车、轻型货车、电单车、机动三轮车** |
| c | 该驾照是**通过驾驶考试后**取得 | 若你最近一次换证不足 1 年、驾照上不显示实习期信息，或含多个准驾车型 → 需**车管所出具的「驾驶执照细节证明文件」**（驾驶人信息/驾龄证明）正本+副本 |
| d | 三选一：① 发照时在发照地居留≥6 个月 ② 申请前**已持照满 5 年** ③ 持有发照地的护照/同等旅行证件 | 大陆人走 ②最省事（持照满 5 年）。①的证明必须含护照出入境记录+签证+学校成绩表/在职证明；**港澳居民居住证、内地房产证不被接受**。③对大陆人不适用（回乡证/居住证不算同等旅行证件） |

> 也就是说：**内地驾照满 5 年 = 最顺的路径**；不满 5 年就得拿出"当年在当地住满 6 个月"的出入境+签证+在读/在职证明。

## 2. 系统真实结构（实测，2026-11）

```
gov.hk/sc/apps/tddiabs.htm            ← 入口（3 秒 meta refresh）
  └─ abs3.td.gov.hk  (React 单页)     ← 勾「同意」→ 点「预约」→ 选「不使用智方便」→ 选「中国内地」
       └─ abs4.td.gov.hk  (排队)      ← 随机分配排队位；实测闲时 20–35 秒放行，17:00 高峰可达数十分钟
            └─ abs1/abs2.td.gov.hk/tdab2/tdabs_di_external/AdminServlet?cmd=cmdGetOfficeQuotaDIAction
                                      ← 老式 JSP 页：
                                         · 有名额 → 出现「继续」进入第 2 步「输入资料」
                                         · 无名额 → 直接红字报错，连表单都不给
```

- 报名链路：第1步认证 → 第2步输入资料（身份证明文件号码/影像 + 驾照号码/影像 + 电邮 + OTP）→ 第3步选牌照事务处/日期/时段 → 第4步递交确认。
- 页面里有 `captchaToken` 字段，第 2/4 步可能出现人机验证 —— **纯脚本无人值守不可靠，必须人在场**。
- 「查询各牌照事务处预约情况」按钮（`cmdGetOfficeBookingStatusAction`）是官方给的名额概览入口。

## 3. 作战时刻表（工作日）

| 时间（HKT） | 动作 |
|---|---|
| 15:50 | 打开本目录 `check.py --show`，确认系统在线；把速填卡、图片、邮箱摆好 |
| 16:00–16:30 | **系统维护，不要刷**。链接会换，旧书签全部失效 |
| 16:30 | 从 gov.hk 页面重新进入（唯一可靠入口），勾同意 → 预约 → 不用智方便 → 中国内地，停在排队页 |
| 16:30–16:55 | 挂着别关；可再开 1–2 个**独立浏览器**（不同 profile / 另一台设备 / 手机流量）各挂一条队列 |
| 16:57 | 双手就位：速填卡、两张图片、邮箱页面、20 分钟计时 |
| 17:00 | 随机洗牌。哪条会话先出来就用哪条，**立刻**走第 2 步 |
| 17:00 + 20 分钟内 | 填资料 → 收 OTP → 选日期时段 → 递交 → 收到 tdabs@td.gov.hk 确认电邮 |
| 17:00 之后 | 没抢到也别走开：**取消/更改的时段会随时回流**，用 `check.py --loop 180` 挂着等 |

> 16:30 之前进池没有意义（官方 FAQ Q15 明说等候时段不排先后，17:00 才随机分配）。所以"提前 3 小时挂机"不如"16:30 准时进 + 多一条队列"。

## 6.5 「像真人」的机制（来自你自己的 tdabs_monitor.py）

`human.py` 把你原脚本里那套节奏设计搬进了 Playwright 版，两个入口脚本共用：

| 你原脚本里的设计 | 移植后的实现 | 效果 |
|---|---|---|
| `_dwell()` 三角分布停顿 + `wander` 走神 | `H.dwell(low, high, mode, wander)` | 停顿有众数不是均匀随机；闲时约 8% 概率"走神"多停 12–40 秒 |
| `jitter()` 盯屏时抖动小、平时偏长 | `H.jitter(base, watching)` | 循环探测不再是固定心跳，约一成会多离开一会儿 |
| `_pick_browse()` 概率决定从哪页续接 | `H.phase_now()` + `_hurry()` | 维护/等候/放号/深夜/周末各用不同节奏 |
| `_open_like_person()` 按真人顺序逐层点 | `H.human_click()` + `H.look_around()` | 先移动鼠标、悬停再按；页面会滚两下再操作 |
| `in_window()` 工作日/时段判断 | `H.phase_now()` → maintenance / waiting / rush / quiet / weekend | 17:00–18:30 自动切 `hurry`，停顿压到最短 |
| `backoff_seconds()` 指数退避 + 熔断 | `H.Backoff`（60→120→240→480→1800 长暂停） | 连续异常不狂点，降低被 WAF 盯上的概率 |
| 全局 TLS/指纹收敛 | `H.apply_mask()` + `--disable-blink-features=AutomationControlled` + 随机 viewport | 抹掉 `navigator.webdriver`、语言/插件特征对齐 zh-HK |
| 会话持久化 | `launch_persistent_context(profiles/wN)` | 每个 worker 独立 profile，排队位互不干扰 |

另外两处是 Playwright 才做得到的：

- **逐字输入**：`H.human_type()` 用 `press_sequentially`（18–130ms/键），不是 `fill()` 一次性注入；可开 `typo_rate` 制造"打错再退格"。
- **元素不稳定时降级**：React 重渲染会让元素一直 "not stable"，现在按 `click → force → dispatch_event` 三级降级，不会干等 10 秒。

实测代价：名额雷达从 31 秒变成约 39 秒（多出来的是真人停顿），换来的是行为特征不再像"每 30 秒精确打一次卡的机器人"。

## 6.6 「用 Playwright 会不会被识别」——实测对比

用 `fingerprint_check.py` 在本机实测了三种内核（结果可复现）：

| 检测项 | Playwright chromium | 真 Chrome 启动 | 真 Chrome 接管(CDP) |
|---|---|---|---|
| `navigator.webdriver` | `False` ✅ | `False` ✅ | `False` ✅ |
| 是否被 JS 补丁覆盖（`hasOwnProperty`） | `False` ✅ | `False` ✅ | `False` ✅ |
| UA 版本 | Chrome/**143** ⚠️ | Chrome/**156** ✅ | Chrome/**156** ✅ |
| `navigator.languages` | `['zh-CN']` | `['zh-CN','zh']` | `['zh-CN','zh']` ✅ |
| `screen` / 窗口尺寸 | 被 viewport 接管 | 真实 | **真实** ✅ |
| WebGL 渲染器 | 真 GPU（Intel Iris Xe）✅ | 同 | 同 |
| `permissions.query` 是否 native | ✅（已删除自造的补丁） | ✅ | ✅ |

**结论：能被"看到"的差异只剩两条**——UA 版本号落后 14 个大版本、`languages` 少一个 `zh`。这两条都不是铁证（很多人就是旧版 Chrome、只设一种语言），而真正的自动化铁证 `webdriver=true` 已经通过 `--disable-blink-features=AutomationControlled` **原生**关掉，没有留下 JS 补丁痕迹。

### 风险排序（按这套系统实际会看的东西）

1. **IP 信誉** —— 官方 FAQ Q20 明写：用 VPN/数据中心网络或 iCloud 私密转送会被判异常、暂时拒绝访问。这是**唯一被官方点名**的判据。
2. **请求频率与行为** —— 已用 `human.py` 的停顿分布、逐字输入、人类式点击压住。
3. **浏览器指纹** —— 华为 WAF（`HWWAFSESID`）+ 排队系统这套组合，常规做法是 IP 限速、排队令牌、表单校验，不会为"免试签发预约"专门跑深度 JS 指纹。

### 三种用法，按风险从低到高

| 方案 | 做法 | 指纹特征 | 适合 |
|---|---|---|---|
| A 纯人工 | 脚本只做提醒，浏览器自己点 | 零 | 只缺一个号，最稳 |
| B 接管真 Chrome | `launch_chrome.ps1` 起真 Chrome，`grab.py --attach http://127.0.0.1:9222` | 几乎=人工（仅多一个调试端口） | **推荐** |
| C 真 Chrome 自动启动 | `config.json` 里 `"channel": "chrome"` | 只有窗口尺寸非真实 | 图省事 |
| D 自带 chromium | `"channel": ""` | UA 版本落后 | 仅演练 |

```powershell
# 方案 B：先起真 Chrome，再让脚本接管
powershell -ExecutionPolicy Bypass -File .\launch_chrome.ps1
python grab.py --workers 1 --attach http://127.0.0.1:9222

# 方案 C：直接让 Playwright 启动本机 Chrome
python grab.py --workers 3

# 随时自查指纹
python fingerprint_check.py --chrome
python fingerprint_check.py --attach http://127.0.0.1:9222
```

有一点必须说清：官方原文写着「任何涉及**异常或可疑活动、未经授权工具**或提供可疑资料的预约亦将会被**取消**」。所以最坏情况是**预约被取消、要重新排队**，而不是被封号。这也是为什么方案 A（人工点、脚本只提醒）永远是兜底。

## 6.7 官方站点返回 502 / 维护页怎么办（2026-11-08 20:18 实测）

当晚 20:15 起 `abs3.td.gov.hk` 与 `abs4.td.gov.hk` 同时返回 **502 Bad Gateway**，而 `gov.hk` 入口页仍是 200 —— 这是**官方后端故障**，不是被限速、也不是脚本问题。

处理方式已经写进代码：

| 脚本 | 行为 |
|---|---|
| `check.py` | 退出码 **30** 并明确提示「官方返回错误页，不是名额问题」；`--loop` 模式下自动拉长到 ≥300 秒再看 |
| `grab.py` | 入口页没有复选框时不再干等，改为退避重试（30s → 60s → … 上限 600s，最多 20 次）；仍失败则记录 `entry_unreachable` 并干净退出 |
| `wait_page()` | 新增 `health=` 探针，每 4 次轮询查一次页面；发现 5xx/维护页立即放弃等待，避免卡 30 分钟 |

**判断口径**：502 只能等官方恢复。此时做任何"提速"都没意义，因为请求根本没到达业务系统。

```powershell
# 盯着它什么时候恢复（每 5 分钟一次，恢复后会报 10/0）
python check.py --loop 300
```

**对明天的意义**：16:30 进池之前先跑一次 `python check.py`。如果那时站点已经是 502，说明当天不具备抢号条件，别在 17:00 白白消耗一次排队机会。

## 6.8 出口 IP 被 WAF 直接拦掉：`Restricted access`（2026-11-09 预演实测）

预演时用 WARP/代理出口（`104.28.x.x`，Cloudflare 网段）跑，链路前段全通，但一点「继续」就进到 `abs4.td.gov.hk` 的拦截页：

```
We are sorry, your access has been restricted
Ip: 104.28.159.222
The website you tried to access has been configured to block access to a configuration that matches yours.
Are you using Apple's iCloud Private Relay feature or other privacy networks like Zscaler?
Avoid any actions that might obscure or hide your IP address.
```

**这不是名额问题，也不是脚本问题**，是华为云 WAF 按出口 IP 段直接判死。判据与官方 FAQ Q20 一致：VPN / 机房 / 隐私中继网络一律拦。

代码现在的行为：

| 脚本 | 行为 |
|---|---|
| `check.py` | 退出码 **40** 并明确写「出口 IP 被官方 WAF 限制」；不再把这种情况误报成「没探到」 |
| `grab.py` | 撞到限制页**约 10 秒内**判定并退出（`stage=ip_restricted`），同时推钉钉；不再干等 600–1800 秒 |
| 被弹回入口页 | `grab.py` 会自动重走「勾同意 → 预约 → 不用智方便 → 内地」（界面变成英文也能点，按钮匹配是中英双语） |

**处理办法只有一个**：关掉 VPN / 代理 / WARP / iCloud 私密转送，用真实家宽或手机 5G。

```powershell
# 换网络后先确认能不能过闸（40 秒内出结果）
python check.py --attach http://127.0.0.1:9222
# 40 = 还是被拦；10 = 通了但没号（这是好消息，说明链路可达）；0 = 有号
```

## 6.9 WAF 的 412 挑战：为什么脚本进不去，人却能进（2026-11-09 血泪）

### 症状

- 浏览器打开 `abs3.td.gov.hk` 一片空白，`body` 只有几十字节
- 裸 HTTP 请求返回 **412 Precondition Failed**，响应体是 5~6KB 混淆 JS
- `check.py` 报 40/41，`grab.py` 卡在入口

### 本质

这是**华为云 WAF 的动态防护挑战**，不是封禁：

```
服务端 → 412 + 一段混淆 JS（含 $_ts / nsd / cd）
浏览器 → 执行 JS → 算出 token → 写入 HIK0kat3rt9xO 等 cookie
       → reload
服务端 → 200，放行
```

那段 JS 会采集浏览器环境。**Playwright 用 CDP 接管会留下可被探测的痕迹**（`Runtime.enable` 之后的 console 包装、`Error.stack` 格式、注入的 `window.chrome` 补丁），于是挑战脚本不发放 token —— 页面就永远空白。人用普通窗口访问则能正常拿到 token。

### 正确姿势（唯一稳定的一条）

```powershell
# 1) 人：在 Chrome 里打开入口，手动过验证，一路点到「中国内地」排队页
#    （排队位置有效，别刷新、别关）

# 2) 脚本：从当前页接管，一个 goto 都不发
python resume.py --attach http://127.0.0.1:9223
```

`resume.py` 只认当前 URL：abs4 就等（打心跳），SelectCountry 就选内地，到 JSP 页就填表上传，然后选日期时段、确认、抓 OTP。**它不会重新进站，所以不会把排队位作废。**

### 三条铁律

| 做法 | 后果 |
|---|---|
| **清 cookie** | 把 WAF token 删了，逼自己重过挑战 → 当晚就是这样把自己搞死的 |
| **失败后反复重试** | 每 45 秒 × 40 次 = 把自己的信誉打到最低，连人工窗口都更难通过 |
| **换 IP 后继续用旧会话** | 会话与 IP 绑定，容易直接 412；先看是不是挑战页再决定 |

### 代码行为（已按上述改写）

| 脚本 | 行为 |
|---|---|
| `waf.py` | 统一识别挑战页：`is_challenge(status, text)` / `detect(page)` |
| `grab.py` | 入口只试 **2 次**；撞上 412/挑战立刻熔断、响铃、推钉钉、**停止一切请求** |
| `check.py` | 退出码 **41 = 被 WAF 挑战挡住**（提示人工过验证 + resume 接管） |
| `resume.py` | 从已排队窗口接管；页面空白连续 5 次即判定挑战、停手喊人 |

## 6.10 无 CDP 方案：Chrome 扩展 + 本地服务（2026-11-09 实测跑通）

### 为什么要换技术栈

实测结论（同一天、同一 IP、同一台机器）：

| 进站方式 | 结果 |
|---|---|
| Chrome 自己导航（命令行/地址栏） | ✅ 200，挑战自动过，页面正常 |
| **CDP 的 `page.goto()`** | ❌ 412 + JS 挑战页，空白 |
| **CDP 点击后触发的导航** | ❌ 200 但只有 39 字节空壳，cookie 从 `…xO` 变 `…xP` |
| curl_cffi 冒充 Chrome JA3 | ❌ 412（说明不是 TLS 指纹问题） |

也就是说：**WAF 能感知 CDP 会话**。所以只要 Playwright 在控制浏览器，就过不去。
解法只有一个——**不要 CDP**。

### 架构

```
launch_ext.ps1
  └─ Chrome for Testing（支持 --load-extension，正式版 137+ 已禁用）
       └─ extension/            ← 页面内 state machine，所有点击/跳转都是页面原生行为
            ├ manifest.json
            ├ background.js    ← 唯一负责和本地服务通信（content 受 CORS 限制）
            └ content.js       ← 识别阶段 → 执行动作（勾选/点预约/选国家/填表/上传/OTP）
       └─ ext_server.py        ← 127.0.0.1:8765：下发配置与图片字节、收状态、供 OTP
```

为什么文件上传也能做：content script 里用 `DataTransfer` 构造 `File` 直接塞进
`input[type=file].files`，不需要 CDP 的 `setInputFiles`。

### 实测日志（2026-11-09 18:47）

```
注入 gov.hk 入口 → 跳 abs3 → 注入
读配置（潘郁明 / 候选办事处 4 个）
勾选同意条款 → 点「预约」
认证页 → 选「不使用智方便」 → 继续
进入 abs4 排队页 ✅（不是 412，不是空白）
排队中（交由官方随机分配）
```

**全程无人值守、无 CDP、无一次 412。**

### 用法

```powershell
# 1) 起本地服务（一个窗口，常驻）
python ext_server.py

# 2) 起浏览器（CfT + 扩展，自己导航进站）
powershell -ExecutionPolicy Bypass -File .\launch_ext.ps1

# 3) 看进度（另一个窗口）
Get-Content runs\ext_status.jsonl -Tail 20
```

首次需要 CfT（约 200MB）：

```powershell
powershell -ExecutionPolicy Bypass -File .\get_cft.ps1
```

### 三个必须知道的坑（都踩过了）

| 坑 | 现象 | 处理 |
|---|---|---|
| 正式版 Chrome 137+ 禁用 `--load-extension` | 扩展静默不加载，`Extensions` 目录为空 | 用 **Chrome for Testing**（`get_cft.ps1`，国内走 npmmirror 镜像） |
| CfT 在此机器上 sandbox 无法访问自身可执行文件 | 页面停在 `about:blank`，连 localhost 都打不开 | 启动加 **`--no-sandbox`** |
| 系统里有个失效代理 `127.0.0.1:10809` | Chrome 连 `127.0.0.1:8765` 也走代理 → 超时 | 启动加 **`--no-proxy-server`** |
| manifest 的 `matches` 不支持显式端口 | `http://127.0.0.1:8765/*` 无效 → 整段 `content_scripts` 被忽略 | 写成 `http://127.0.0.1/*`；**且不要依赖 content_scripts**，改由 background 用 `chrome.scripting.executeScript` 主动注入 |

### 与旧方案的关系

| 方案 | 自动化程度 | 何时用 |
|---|---|---|
| **扩展（本节）** | 全自动，无需人工 | **首选** |
| `resume.py` | 人工过验证 + 脚本接管 | 扩展方案出问题时的兜底 |
| `grab.py` | 有 CDP，会被 412 挡 | 仅本地演练/结构侦察 |

## 7. 会翻车的 7 个坑

1. **用 VPN / 机房 IP**：官方 FAQ Q20 明说可能被判定异常而拒绝访问。用本地家宽或手机 5G。
2. **书签旧链接**：16:00–16:30 更新后链接会变，每次从 `www.gov.hk/sc/residents/transport/drivinglicense/diabs.htm` 进。
3. **资料不一致**：证件号/驾照号与证件不符 → 预约直接作废，且运输署会把资料拿去和发证机关核对，查无此人自动取消。
4. **重复预约**：一个申请人多个有效预约 → 全部取消。多开队列只为提高中签率，中了一条就关掉其余。
5. **忘了核实电子联络方式**：递交前 3 个月内没做 OTP 核实 → 柜台不受理。
6. **用临时/一次性邮箱**：系统直接拒收，OTP 也收不到。
7. **抢到却迟到或缺席**：逾时/缺席要重新预约，等于白抢。最迟可在预约时间 **3 小时前**改期或取消。

## 8. 没有香港手机号怎么办（结论：不影响）

运输署 2024-11-18 起的规则原文：申请人必须提供及核实**一个香港流动电话号码 _或_ 电邮地址**作为「电子联络方式」，核实后才能处理申请。也就是说——

- **电邮可以完全替代香港手机号**，二选一，不是二选二。
- 预约系统里「手机号」不是必填项（官方准备清单只列了身份证明文件、驾照、电邮），没有港号就**留空**；若报错，清空这栏继续。
- 柜台递交前要做的核实，走这个官方平台（3 分钟内完成）：
  `https://econtact.td.gov.hk/vansweb/app895_sc.html`
  1) 申请类别选「驾驶执照」，证件类型与预约时保持一致
  2) 输入身份证明文件号码（通行证号或护照号）
  3) 输入**电邮地址**收 OTP → 核实
  4) **截图保存确认页面**，柜台可能要看
- 核实记录**有效期 3 个月**，一次核实可用于多个牌证申请，覆盖整个预约就诊周期，抢号前后做都行，但必须在**去柜台之前**完成。
- 若该平台对通行证号报错，改用护照号做核实即可（这一步与预约填的证件相互独立）。
- 将来告票、牌照通知都走这个电邮，所以要选长期常用、能收境外邮件的邮箱；换联络方式要在 72 小时内通知运输署。
- 真想要港号（可选，非必需）：便利店买 SoSIM / CMHK 储值卡（约 HK$33–50），香港 SIM 卡需实名登记，可用护照或通行证登记；但为此专门跑一趟香港不值。

## 9. 抢不到时的 B 计划

- **换办事处**：九龙/观塘/沙田只收内地驾照，香港牌照事务处也收内地驾照（且收所有认可地区），别只盯一个。
- **盯回流名额**：`check.py --loop 180` 常挂，取消/更改的时段会重新开放。
- **改日期不改身份**：已预约后不能改资料，只能在 3 小时前改时间/取消后重约。
- **临时驾照走不通**：内地驾照在附表4 内，TD181 临时驾照只给**非**附表4 地区的驾照持有人，内地驾照不适用。
- **电话**：1823（预约系统）、2804 2600 / 2804 2693（牌照事务组）。
