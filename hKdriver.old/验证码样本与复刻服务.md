## 一、样本库（已有 23 个）

```

  manifest.json            索引：id / 类型 / 尺寸 / dx / 是否验证
  spec_<id>.json           归一化样本（23 个）
  raw_<id>.json            扩展实时上报的原始样本（含 DOM / 几何 / 环境 / scan）
  bitmaps/<id>.png         原始 canvas 位图
```

| 类型 | 数量 | 来源 |
|---|---|---|
| `canvas_bitmap` | 11 | 扩展 `toDataURL` 发来的原始画布（400×330） |
| `annotated` | 7 | `locate_shapes` 画了绿/红框的调试图 |
| `dpr_variant` | 2 | DPR=2 环境（位图 800×660） |
| `slider_shot` / `unknown` | 2 | 滑块调试截图 |

用当前算法回填 `dx` 后，`annotated` 与 `dpr_variant` 全部可解（`shape=4-gon dx=180`、DPR 变体 `dx=360`），
也就是说这批历史图可以直接当回归用例。

## 四、怎么接你的脚本

只有一处要改：把求解请求的地址从 `http://127.0.0.1:8765` 换成 `http://127.0.0.1:8777`，
入参字段完全一致（`dataUrl / bmpW / bmpH / cssW / cssH / dpr / inFrame / trackW / handleW / seed`）。

```python
from curl_cffi import requests as cr
ch = cr.get("http://127.0.0.1:8777/challenge?seed=424242").json()
an = cr.post("http://127.0.0.1:8777/analyze", json={
    "dataUrl": ch["dataUrl"], "bmpW": ch["bmpW"], "bmpH": ch["bmpH"],
    "cssW": 400, "cssH": 330, "dpr": 1, "inFrame": False,
    "trackW": ch["geom"]["trackW"], "handleW": ch["geom"]["handleW"], "seed": ch["seed"],
}).json()
print(an["dx"], an["slider_dx"], an["truth_dx"], an["err"])
```

判定走 `/grade`（容差可调：`TOL=2 node server.js`），真值只在这里出现。

## 五、复刻服务能证明什么、不能证明什么

能证明：**识别链路**（阈值分档、实心/空心配对、行程换算）在你自己的脚本里是对的，且可复现（固定 seed）。
不能证明：能过真站的风控 —— 真站还会看轨迹特征、耗时、isTrusted、指纹一致性。
所以定位是「把回归测试从"等下次弹码"变成"随时 30 秒跑 30 道题"」。

## 六、已知缺口

1. 复刻题只覆盖 **重合类滑块**（实心/空心）；MTCaptcha 的图片点选没有复刻，也没有真样本落盘（线上还没弹过）。
2. 复刻页的拖动是手拖验证，脚本要走接口的话请直接用 `/grade` 提交 `sliderDx`。
3. `spec_*.json` 里的 `ground_truth.verified` 只代表「当前算法在这张图上算出了值」，不代表是真实答案；
   真实答案只有 `live` 样本（若当时求解成功）与人工核对才能确认。
