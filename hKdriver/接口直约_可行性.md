# 抓接口直约：可行性结论与工具（2026-11-09 深夜实测）

## 一句话结论

**能，但只能是「浏览器养会话 → 接口跑业务」的混合式，不是「纯 HTTP 无人值守」。**
会话一旦在浏览器里过了 WAF 挑战、拿到 abs4 排队放行、停在 JSP 填表页，
后面**每一次提交都是明文字段 POST**（第 1 步 71 个字段全在页面里），
用 `replay.py` 按顺序重发即可，包括最后的「递交确认」——只要 OTP 从邮箱自动捞。
反过来，**没有任何会话的裸 HTTP 连第一道门都进不去**（下面有实测）。

---

## 二、今晚实测证据（可复现）

| 实验 | 请求 | 结果 | 含义 |
|---|---|---|---|
| 1 | `curl_cffi(impersonate=chrome124)` GET `abs3.td.gov.hk` / `abs2…cmdGetOfficeQuotaDIAction` | **200**，708 字节 React 壳，下发 `HWWAFSESID` | 此刻 WAF 的 412 挑战**没有**触发；不是 TLS 指纹问题，`curl_cffi` 能过网关 |
| 2 | 上面这个 GET 实际被 **302 到 `abs3.td.gov.hk/?lang=en`** | 200 + SPA 壳 | host 路由：没有会话就只给 SPA，业务 JSP 不给你 |
| 3 | POST `AdminServlet_schinese?cmd=cmdGetOfficeQuotaDIAction`（带 `storedAppointmentServiceType=DI`、`isAuthConfirm=Y`、`IssuingCountry=CN`） | **302 → `abs3.td.gov.hk/?lang=en`**，下发 `JSESSIONID` | 第 1 步提交是纯表单 POST，但服务端要求「排过队」的会话状态 |
| 4 | 带着上面那个 `JSESSIONID` 再 POST 一次 | **仍然 302** | 光有 JSESSIONID 没用：队列放行状态是服务端会话属性，抄不到、造不出 |

**结论链**：业务字段 100% 可重放；拦住纯 HTTP 的不是字段，而是**会话里的三张票**。

## 三、三张票 + 一个验证码：谁提供

| 要素 | 从哪来 | 能否纯 HTTP 伪造 | 处理 |
|---|---|---|---|
| 华为 WAF token（`HWWAFSESID` / `HIK0kat3rt9xO`） | 浏览器执行挑战 JS 后写入 | 否（要跑混淆 JS + 环境采集） | 浏览器过闸，cookie 由扩展 `chrome.cookies` 导出 |
| abs4 排队放行状态 | 17:00 随机洗牌后，服务端在会话里置位 | 否（无对应接口，也不可跳） | 多开队列，哪条先放行用哪条 |
| MTCaptcha token（`captchaToken`） | 页面里 MTCaptcha 组件（滑块/点击）产出 | 否（服务端二次校验） | `slider.py` 自动拖 + `captcha.py` 兜底；实在过不去就人拖一下 |
| 邮箱 OTP（`storedAppointmentOtpCode`） | `tdabs@td.gov.hk` 发到登记邮箱 | 否 | `mail_watch.py` 已跑通 IMAP 取码，写 `otp.txt` → `ext_server` 的 `/otp` |

> 补一句：第 1 步表单里还有一个 `storedAppointmentIAMSmartHelperJwt`，是页面 JS 现算的
> 短签名（`iAmSmartHelper.authentication.init()`），抓包时拿到的是**那一次**的；
> 隔夜重放它多半会被判旧 → 这也是「必须浏览器养会话」的另一个理由。

## 四、已确认的接口清单

| # | 方法 | 地址 | 说明 |
|---|---|---|---|
| 1 | GET | `https://www.gov.hk/sc/apps/tddiabs.htm` | 入口（3 秒 meta refresh） |
| 2 | — | `abs3.td.gov.hk`（React） | 勾同意 → 预约 → 不用智方便 → 中国内地；**MTCaptcha 在这层** |
| 3 | — | `abs4.td.gov.hk`（排队） | 17:00 随机洗牌，放行后写会话状态 |
| 4 | POST | `abs1/abs2.td.gov.hk/tdab2/tdabs_di_external/AdminServlet_schinese?cmd=cmdGetOfficeQuotaDIAction` | **第 1 步提交**。表单 `frmAppointment`，字段全明文；有名额才回第 2 步 |
| 5 | GET | 同上 `cmd=cmdGetOfficeBookingStatusAction&serviceTypeCode=DI&storedAppointmentOperation=A&storedAppointmentExpiryDate=DD-MM-YYYY&enablePick=N` | 各办事处名额概览（弹窗用） |
| 6 | POST | 第 2 步：填资料 + 上传（返回 `…Uuid` 回填 `storedAppointmentIdentityDocumentUuid` / `…DrivingLicenceProofUuid`） | 上传是独立请求，**要抓一次**才知道实际 cmd |
| 7 | POST | 第 3 步：`storedAppointmentOfficeCode` / `TimeslotDate` / `TimeslotFromTime` / `TimeslotToTime` / `TimeslotId` | 选办事处+时段 |
| 8 | POST | 第 4 步：递交确认（含 `storedAppointmentOtpCode`、`captchaToken`） | 成功后发 `tdabs@td.gov.hk` 确认信 |

第 2~4 步的 action 名字要到有名额时才会出现在页面上，**抓一次就永久有**——这正是下面工具干的事。

页面还会下发一个硬时限：`const maxAgeMillis = 1200000`（20 分钟），服务端同样校验。

## 五、工具：抓包 → 重放（已接好）

### 抓

```
netrec.js（页面主世界，钩 form.submit / XHR / fetch，只在 AdminServlet 页生效）
  → netrelay.js（隔离世界）
    → background.js（顺手带出 td.gov.hk 全套 cookie，含 HttpOnly）
      → ext_server.py  POST /net  →  runs/net/net.jsonl
```

为什么只钩 JSP 页：WAF 挑战脚本在 abs3/abs4 上跑，会检查原生函数是否被改写；
业务页已在 WAF 之后，风险最低。钩子函数的 `toString` 已伪装成 `[native code]`。

启动方式不变：

```powershell
python ext_server.py                              # 常驻
powershell -ExecutionPolicy Bypass -File .\launch_ext.ps1
# 浏览器走到 JSP 填表页、点过一次「继续」后：
Get-Content runs\net\net.jsonl -Tail 5
```

### 重放

```powershell
python replay.py --list                 # 抓到了哪些接口
python replay.py --show                 # 重放计划（字段脱敏，文件字段标出本地映射）
python replay.py --send --skip-final    # 真发，但停在最后一步（不占号，用来验证会话）
python replay.py --send                 # 一路发到递交
python replay.py --send --only 2        # 只发第 2 条
```

`replay.py` 用抓包那一刻的 cookie 直接重建会话（`curl_cffi`，`verify=False` 只是绕开本机过期 CA），
文件字段按 `config.json` 里 `doc_file` / `dl_file` 的路径补回真实字节。
退出码：`0` 全通 / `10` 被业务拒绝（含无名额）/ `20` 会话失效（回浏览器重新抓）/ `30` 没有抓包。

## 六、收益与代价（别高估）

| 项 | 接口重放 | 页面自动化（现有扩展） |
|---|---|---|
| 每步耗时 | 0.2~0.6 秒 | 1~3 秒（等 React 重渲染/滚动/人类停顿） |
| 全流程节省 | 约 **8~20 秒** | — |
| 多办事处/多时段快速试选 | 容易（循环改字段重发） | 要重新点 DOM |
| 抗 WAF 能力 | 依赖浏览器会话，**不能独立存活** | 全在页面内，天然一致 |
| 失效风险 | 会话过期 / 页面签名（IAMSmart JWT、timestamp）过期 | 低 |

真正决定能不能约到的是 **17:00 那次随机洗牌**，不是点按钮快 10 秒。
所以定位应该是：**扩展负责进站排队与过验证，`replay.py` 负责抢到之后把 20 分钟窗口用满**——
尤其是「选时段」那一步，可以一口气把 4 个办事处 × 多个日期全试一遍，不必等页面逐次刷新。

## 七、执行顺序（17:00 当天）

1. 15:50 `python check.py` 确认站点在线（30/40/41 都别硬上）。
2. 16:30 扩展版浏览器进池，多开 1~2 条队列；`python ext_server.py` 常驻。
3. 17:00 哪条放行用哪条；页面到 JSP 填表页后，`runs/net/net.jsonl` 会自动开始记录。
4. 先跑 `python replay.py --show` 看清字段，再 `--send --skip-final` 验证会话是否可重放。
5. 会话可重放 → `--send` 走完；OTP 由 `mail_watch.py` 写 `otp.txt`，`replay.py` 会带 `storedAppointmentOtpCode`。
6. 一次只完成一条预约（同一身份多个有效预约会被全部取消）；其余窗口关掉。

**三条铁律不变**：不清 cookie、失败不狂重试、换 IP 后不硬用旧会话。
