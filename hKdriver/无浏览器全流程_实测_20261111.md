# 无浏览器跑全流程：实测通过（2026-11-11 14:10–14:35）

> 结论：**从「盯排队」到「第 1 步判号」这一段，已经可以完全不开浏览器。**
> 人工只需要做一件事：进站过掉人机验证（一次），然后导出 cookie，后面交给 `sniper.py`。
>
> 全部步骤都是实测，不是设计稿。命令可直接复制。

## 二、链路图（哪些要人、哪些不要）

```
        ┌───────────── 人做一次 ─────────────┐
        │ 在 Chrome 里进站 → 过人机验证 →      │
        │ 停在 abs3/SelectCountry             │
        └──────────────┬──────────────────────┘
                       │  python runs/rev/grab_page.py
                       ▼
              runs/rev/browser_cookies.json        ← 15 条 cookie（含放行票）
                       │
   ┌───────────────────▼───────────────────────────────────────┐
   │  之后全部无浏览器（sniper.py）                              │
   │                                                           │
   │  ① GET  abs3/?lang=sc                 → HWWAFSESID       │
   │  ② GET  abs3/SelectCountry?…          → 302，取 c/e/t     │
   │  ③ POST abs4/spa-api/queue/…/enqueue  → queueId（新票）   │
   │  ④ POST abs4/spa-api/queue/…/status   → 排队位/ETA        │
   │  ⑤ GET  {t}（http→https）             → 业务页            │
   │  ⑥ GET  abs1/…AdminServlet?cmd=cmdIntoSelectAuthDI        │
   │     POST AdminServlet_<lang>?cmd=cmdGetOfficeQuotaDIAction │
   │           └─ 页面自己报「有没有名额」+ TrackId              │
   └───────────────────────────────────────────────────────────┘
```

> 注意 ①③ 与 ⑥ 用的是**两套不同的东西**：
> - ①③ 是「没有浏览器会话时自己排队拿票」的路；
> - ⑥ 必须带**浏览器那套放行 cookie**（`QueueITAccepted-*` + `urltoken`），
>   新建的 ticket 不能直接换业务访问权。

## 三、五个必须记住的坑（都已写进代码）

| 坑 | 现象 | 正确做法 |
|---|---|---|
| 表单 `action=""` | 直接 POST 回 GET 的 URL → 只拿到错误页 | action 由页面 JS 设置：`frmAppointment.action = '/tdab2/.../AdminServlet_tchinese?cmd=cmdGetOfficeQuotaDIAction'`，**必须现场解析**（`sniper.step1()` 已这么干） |
| 繁体页是 **Big5** | 用 UTF-8 解全是 `闆㈤枊` 这类乱码，判号全错 | 按 `utf-8 → big5 → big5hkscs → gb18030` 依次试（`Sniper._decode()`） |
| Queue-it 的 `t=` 是 `http://abs3…` | 80 端口连不上（abs3 只开 443），21 秒超时 | 自动改写成 `https://` |
| `forecastStatus=FirstInLine` | 排到第一位但队列不动（实测持续 3 分钟） | **放行只认 `status.redirectUrl`**，别拿 FirstInLine 当放行 |
| `eventId` 会变 | 隔天 `tdabsd261111kla` → 400 Bad Request | 一律走 ② 动态发现；`--reuse-event` 只在同场次重试时用 |

## 四、命令

```powershell
# ---- 第一段：人过验证（只做一次）
python sniper.py --probe                 # 先确认 WAF/排队链路通（6 秒）
#   在浏览器里点：同意 → 预约 → 不用智方便 → 中国内地 → 过验证
#   停到「选择国家/地区」页后：
python runs\rev\grab_page.py             # 导出 cookie + 当前页 HTML/存储

# ---- 第二段：之后全部无浏览器
python sniper.py --cookies runs\rev\browser_cookies.json --step1
#   0 = 有名额（会话可用，可以进第 2 步）
#  10 = 无名额（正常，工作日 17:00 更新）
#  42 = 会话没放行（cookie 过期 / 换过 IP）

# ---- 没有浏览器会话时，自己排队盯放行
python sniper.py --watch --minutes 40    # 一放行就停
python sniper.py --run --worker w1       # 放行 → 进业务 → 判号
```

## 五、17:00 当天怎么用（两段式）

| 时间 | 动作 | 命令 |
|---|---|---|
| 15:30 | 站点体检 | `python check.py` |
| 16:30 | 人进池（一次即可），过完验证停到国家页 | 扩展 / 手工 |
| 16:40 | 导出 cookie（**放行后再导**，早导的是排队前的票） | `python runs\rev\grab_page.py` |
| 16:45–16:59 | 无浏览器挂机盯排队位（可选，另开一条） | `python sniper.py --watch --minutes 20` |
| **17:00** | 名额刷新后立刻判号，有号就抢 | `python sniper.py --cookies runs\rev\browser_cookies.json --step1` |
| 17:00+ | 判到 0 → 立刻交接「第 2 步」 | `python replay.py --send --skip-final` / 扩展 content.js 接手 |

> 为什么 17:00 之后还要把浏览器拉回来：第 2 步的**上传**与第 4 步的**递交**
> 带 `storedAppointmentIAMSmartHelperJwt` / `captchaToken`，这两个是当场签名，隔夜/跨窗口必废。
> 纯 HTTP 能做的是「判号 + 快速试选时段」，不能替它签。
