## 8. 第二轮实测（17:24–17:31）：dx 算得准，死在「拖不动」

### 8.1 题目结构（这次彻底看清）

华为云 WAF 的 Quidditch 滑块是**跨两层**画的：

| 层 | 内容 | 取法 |
|---|---|---|
| canvas 2D 层 | **实心形状**（要拖动的那个）+ 滑轨 + Submit | `canvas.toDataURL()` |
| CSS background 层 | **空心轮廓**（目标）+ 网格 + 装饰 | `background-image` |

三种文案（同一机制的变体）：

- `Move the slider so the solid shape lands on the hollow one.`
- `Adjust the slider until the two shapes line up.`
- `Drag the slider until the solid and hollow shapes overlap.`

### 8.2 dx 算得对（跨层配对）

`slider.locate_cross()` 在真实样本上的结果，与整页截图目视一致：

| 样本 | 实心 (x) | 空心 (x) | dx | 形状 |
|---|---|---|---|---|
| `captcha_172737` | 168.3 | 214.4 | **46.05** | 8-gon / 8-gon |
| `captcha_172806` | 174.6 | 214.4 | **39.79** | 8-gon / 8-gon |
| `captcha_172856` | — | — | **57.2** | 8-gon / 8-gon |

### 8.3 死因：拖动只对了一部分（比例不是 1:1）

17:28:56 – 17:29:32 连续四张 canvas **sha256 完全一致**（`484A392496C0520C`），
说明这一段确实没拖动；但 17:29:56 / 17:29:59 两张换了 sha，图形开始移动：

| 样本 | 手柄 x | 图形 x | 服务端算出的 dx |
|---|---|---|---|
| 172856 (17:28:56) | 27.5 | 160 | 57.2 |
| 172956 (17:29:56) | 94.5 | 180 | 36.8 |
| 172959 (17:29:59) | 131.5 | 193 | 23.9 |

**滑轨走 104px，图形只走 33px ⇒ 行程比 ≈ 0.317**（三次测量 0.299 / 0.351 / 0.317）。

而 solver 一直按 **1:1** 拖：拖 57px 只补掉 18px，下一轮再按剩余量拖，又只补 31.7%……
所以表现为「每轮都在动，但永远差一点」，直到浏览器被关掉都没收敛到 0。

修正后的口径：

- 要消除 `dx`，手柄必须走 `dx / 0.317 ≈ 3.15 × dx`
- 滑轨全长 369px ⇒ 图形最大可位移约 **117px**
- 拖完重新量一次再按比例补一次，两步就能到位

## 10. 最致命的一处：提交按钮点错了（2026-11-16 17:5x 修）

### 10.1 DOM 里那个 `#swap` 不是提交

`runs/runlog/2026-11-16/055_*/dom.html` 里只有这一个候选：

```html
<button id="swap" class="submit" type="button">Try another verification</button>
```

文案是 **「Try another verification」= 换一题**。

而原代码是：

```js
const btn = document.querySelector("#swap, button.submit") || clickableByText(TEXT_SUBMIT);
if (btn) { btn.click(); }
```

`#swap` 同时命中 id 和 class，所以**每轮拖到接近目标后，点的都是「换一题」**——
于是 dx 从 53 → 8.6，点一下 → 换新题 → dx 回到 32/18/53。
这正是「每轮都在动、永远差一点、永远过不了」的完整闭环。

### 10.2 真正的 Submit 画在 canvas 里

实测 420×428 的 canvas：Submit 中心 **`(210, 402)`** → 比例 `(0.5, 0.945)`，DOM 里没有对应节点。
普通 `element.click()` 摸不到它，必须在 canvas 坐标上派发点击。

### 10.3 改法

```js
// ④ 提交：canvas 内坐标，优先可信点击（同点 trustedDrag），失败退配合成事件
const sp = submitPoint(c);                       // rect.left + w*0.5, rect.top + h*0.945
const okClick = await clickTrusted(sp.x, sp.y);   // chrome.debugger Input，isTrusted=true
if (!okClick) clickSyntheticAt(c, sp.x, sp.y);    // PointerEvent/MouseEvent 全套
```

`clickTrusted` 复用 background 已有的 `trustedDrag`：`from === to`、单点 `points`，
等价于一次真实点击（press → release）。

### 10.4 三个真凶汇总（按发现顺序）
