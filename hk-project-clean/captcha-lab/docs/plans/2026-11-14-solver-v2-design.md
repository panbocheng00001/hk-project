# captcha-lab v2 设计记录：从评测项目到识别工具包

日期：2026-11-14
状态：已实现

## 1. 背景

v1 的定位是"滑块验证码防守实验室"：一切都从出题方视角出发，`solver/` 只作为
红队基线，用来测量自己的题有多难。这个定位对一个想复用识别能力的公共项目是
错的——使用者要的是"给我一个能出 x 和轨迹的东西"，而不是"帮我评估我的题"。

v2 把视角反转：**识别是一等公民，出题与风控退化为可选的评测模块**。

## 2. 目标与非目标

目标：

1. 一条流水线：图片 → 缺口 → 距离 → 轨迹 → 站点载荷；
2. 站点差异收敛到数据（`SiteProfile`），换站点不改内核；
3. 三种对接形态覆盖"已有请求链路 / 标准 JSON 接口 / 真实浏览器"；
4. 可量化：hit@1、hit@topk、耗时、轨迹风险分都有命令可复现；
5. 可部署：HTTP 服务、Dockerfile、CI。

非目标（v2 不做）：点选/文字题的统一接口、分布式任务队列、模型训练流水线
（留了脚手架，见路线图）。

## 3. 架构决策

### 3.1 引擎与适配分层

`SliderSolver.solve()` 只产出"缺口中心 x / 左边缘 x / 距离 / 轨迹点"，
站点口径（center vs left）、字段名、缩放规则都在 `SiteProfile`。
这样新增站点是加一条数据 + 一个 payload 测试，不动识别代码。

### 3.2 多候选而非单点

`gap.locate()` 返回 top-k，`Answer[]` 每个都带距离与置信度。
`solve_until(fetch, submit)` 把"一次命中率"变成"业务成功率"：
第一个候选失败就换下一个，整题失败就刷新重来。
置信度用自适应 softmax（温度 = 最高分 × 0.18），是相对值，用于排序与降级判断。

### 3.3 融合改为"族内一票"

多尺度盒能量对同一区域产出 3–6 条候选，逐条累加会让"碰巧多尺度命中"的背景
区域压过真缺口。改为：按策略族（box/canny/tpl/shadow/projection/diff）取最高票，
再跨族求和 + 按中心距聚类。

### 3.4 精修改为保守

v1 的亚像素精修在 ±30% 宽度内找梯度峰，实测经常抓到缺口右下角的阴影边，
把 1px 误差放大到 5–9px（88% → 75%）。v2 改为局部"四边梯度 − 内部梯度"最大化，
只允许 ±2.5px 位移、±2px 宽度变化。

### 3.5 修掉 `"diff" in method` 的子串误判

`tpl_sqdiff` 里含 `diff`，旧代码给模板候选白送 0.6 分。改为按策略族精确匹配。
这一处 + 尺寸先验，把 hit@1 从 88% 提到 96.7%。

### 3.6 轨迹三层模型 + 自检

运动学（最小加加速度）、人类噪声（手颤/漂移/停顿/过冲）、格式适配。
`audit_risk=True` 时用 `defense.trajectory` 打分并重采样，把"像不像人"变成可回归指标。
四套档案在规则风控下风险分均为 0.00；旧 `human_track` 保留为 100% 被拦的负样本。

## 4. 取舍

| 取舍 | 选择 | 理由 |
|---|---|---|
| 是否引入深度学习检测器 | 暂不默认 | 保持零模型、零下载、CPU 66ms；模型作为可选增强 |
| 是否保留 defense/ | 保留 | 它是轨迹/定位的回归基准，也是差异化能力 |
| 是否内建真实站点适配 | 只给字段口径，不内置接口 | 站点会改版，接口层应留在使用者侧 |
| 置信度是否校准成概率 | 未校准 | 没有真实成功率样本时，校准会给出虚假精度 |

## 5. 测试策略

- 合成样本断言 hit@1（不追求绝对精度，追求"算法不退化"）；
- 口径换算用"center − left ≈ 半个拼图块宽度"这种结构性断言，而不是魔法数字；
- 轨迹用性质断言：终点精确、时间单调、风险分低于阈值、同 seed 可复现；
- 服务用接口契约测试（含鉴权、错误码），不依赖真实网络。
