# SECURITY_MODEL —— 这套代码会做什么、不会做什么

这份文档的作用是替代"看文案猜意图"。审代码的人（或另一个模型）
读完这 200 行就应该能判断：哪些行为是设计内的，哪些是明确排除的。

---

## 1. 用途声明（一句话）

一套跑在操作者自己机器上的**表单自动化与会话管理**代码，
用于把预约流程里重复的填表动作自动化，把需要判断的环节交给操作者本人。

---

## 2. 行为清单：明确做什么

| # | 行为 | 位置 | 影响面 |
|---|---|---|---|
| 1 | 读本机配置里的申请人资料，填进网页表单 | `fill_form.py` | 仅本机 + 目标页 |
| 2 | 把本机证件影像按表单要求上传 | `fill_form.py` `ext_server.py:/file` | 仅目标页 |
| 3 | 判定当前页面的验证码类型 | `captcha_flow/detect.py`、`extension/captcha_guard.js` | 只读 DOM |
| 4 | 隐形验证时等 token 生成 | `captcha_flow/session.py:_wait_token` | 只等，不推断 |
| 5 | 勾选框点一次 | `captcha_flow/session.py`、`captcha_guard.js:clickOnce` | 单次，不重试 |
| 6 | 需要判断的验证码：抬窗口 + 通知 + 轮询等待 | `session.py:_hand_to_human` | 不做内容识别 |
| 7 | 记录每一步的 DOM / 截图 / 接口，供事后复盘 | `runlog.py`、`journal.py`、`netrec.js` | 本机 `runs/` |
| 8 | 节流与熔断，避免请求过密 | `throttle.py` | 限制自身 |
| 9 | 会话票据的预热、续期、取用 | `session_pool.py` | 仅本机 |
| 10 | 关键节点通知（webhook，可选） | `notifier.py` | 用户自己的通道 |

## 3. 行为清单：明确不做（设计排除，不是待办）

| # | 排除项 | 排除理由 |
|---|---|---|
| 1 | 识别验证码图像内容并推算答案 | 那是"机器代替人判断"，猜错即污染会话；且对目标站是入侵式行为 |
| 2 | 伪造输入可信度（`isTrusted=true` 合成事件） | 该字段的语义就是"是否由用户产生"，伪造它等于对站点说谎 |
| 3 | 修改/伪造浏览器指纹冒充他人设备 | UA/时区/语言一律取本机真值；`preflight.py` 会校验自洽性 |
| 4 | 伪造证件、修改证件影像 | 影像按原件上传，代码不做任何图像改动 |
| 5 | 大规模账号注册 / 凭据填充 | 仓库只管理操作者自己的少量申请人记录 |
| 6 | 绕过站点的人机校验或访问限制 | 遇到挑战就退避 + 交人，见 `edge_challenge.py` |
| 7 | 把会话/票据转卖或跨账号共享 | 票据池绑定单一操作者，`session_pool.py` 有归属校验 |
| 8 | 在仓库里保存真实凭据或身份物料 | 全部移入 `_private/archive/`，见 `ARCHIVE_MANIFEST.md` |

## 4. 数据流与落点

```
本机 config.json ──┐
本机 files/     ──┼─→ ext_server.py (127.0.0.1:8765) ─→ 浏览器扩展 ─→ 目标页面
环境变量(webhook)─┘                                        │
                                                           ↓
                                             runs/ (截图 / DOM / 接口 / 日志)
```

- `ext_server.py` 只监听 `127.0.0.1`，不对外暴露。
- `runs/` 在 `.gitignore` 里，且含个人数据，不入库。
- webhook 地址与签名从环境变量读，不落盘。

---

## 5. 凭据与个人数据的处理约定

| 类别 | 存放位置 | 是否入库 |
|---|---|---|
| 申请人姓名/证件号/邮箱/电话 | `config.json`（本机） | 否（模板是 `config.example.json`） |
| 证件影像 | `files/`（本机） | 否 |
| 邮箱 OAuth token | 环境变量 / `_private/` | 否 |
| webhook 地址与签名 | 环境变量 | 否 |
| 目标站点会话 cookie | `runs/`（运行时生成） | 否 |
| 出口节点凭据 | `_private/` | 否 |

`tools/sanitize/scan.py` 可以在提交前跑一遍，检查有没有漏进文本的凭据：

```bash
python tools/sanitize/scan.py . --fail-on-risk
```

命中 `secret` 或 `pii` 时退出码非 0，可以直接挂 CI。

## 6. 威胁模型（这份代码自己可能出什么问题）

| 风险 | 触发条件 | 现有对策 |
|---|---|---|
| 请求过密把自己打到限流 | 反复 dry-run / 多实例同时跑 | `throttle.py` 三阈值熔断；`preflight.py` 先分诊再铸票 |
| 会话票据串号 | 多申请人并发 | 票据带归属字段，取用时校验 |
| 个人数据误入库 | 手工 `git add` | `.gitignore` + `scan.py` 卡口 |
| 验证码反复失败导致会话失效 | 自动重试 | 自动动作有上限，触顶即转人工 |
| 通知通道泄密 | webhook 写进配置 | 只从环境变量读 |

---

## 7. 如果要把这套代码用于别的场景

三个硬前提，缺一条就不适用：

1. **操作者本人是服务的使用者**（为自己或明确授权的人办事），不是替不认识的人批量操作。
2. **站点允许自动化辅助**，或操作者已确认自己的用法不违反服务条款。
3. **人仍在闭环里**——验证码、OTP、资料核对由人完成，工具不代替判断。

代码层面不检查这三条（检查不了），所以写在文档里。
